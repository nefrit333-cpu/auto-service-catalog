# auto-service-catalog

Учебный portfolio demo сайт городского автосервиса в Москве. Проект сделан для практики React, TypeScript, роутинга, компонентной структуры, каталога услуг, фильтров и многошаговой формы записи.

Это не сайт реальной компании. Контакты условные, заявки не отправляются на сервер, отзывы, рейтинги и неподтверждённые показатели не используются.

Опубликованная версия: `https://nefrit333-cpu.github.io/auto-service-catalog/`.

## Технологии

- Vite
- React
- TypeScript
- React Router
- lucide-react для иконок
- Обычный CSS без тяжёлых UI-библиотек

## Что реализовано

- Главная страница со светлым hero, быстрыми категориями, популярными услугами, процессом записи и demo-плашкой.
- Каталог услуг с карточками и фильтром по категориям без перезагрузки страницы.
- Страницы отдельных услуг по маршруту `/services/:slug`.
- Страница контактов с demo-адресом и пояснением, что проект учебный.
- Многошаговая форма записи в модальном окне.
- Локальные demo-изображения в `src/assets/`.

## Страницы

В локальной разработке маршруты выглядят как обычные пути. На GitHub Pages проект использует `HashRouter`, поэтому публичные ссылки открываются через `#`:

- `#/` — главная страница.
- `#/services` — каталог услуг.
- `#/services/:slug` — детальная страница услуги.
- `#/contacts` — demo-контакты.

## Данные услуг

Данные лежат в `src/data/services.ts`. Каждая услуга содержит:

- `id`
- `slug`
- `title`
- `category`
- `shortDescription`
- `description`
- `priceFrom`
- `duration`
- `includes`
- `clarifications`
- `popular`

Категории описаны в том же файле: ТО, диагностика, тормоза, подвеска, электрика и кондиционер.

## Форма записи

Форма открывается как modal overlay и работает только на стороне frontend.

Шаги:

1. Выбор услуги.
2. Автомобиль и описание задачи.
3. Контакты и удобное время.

Если открыть форму со страницы услуги, услуга уже выбрана. Пользователь может изменить выбор. На обязательных полях есть простая валидация. При demo-отправке вызывается `event.preventDefault()`, данные никуда не отправляются, а интерфейс показывает success-состояние.

## Ограничения

- Backend не добавлен.
- База данных не используется.
- Авторизации и оплаты нет.
- Форма не отправляет данные в CRM, email или API.
- Контакты и адрес имеют demo-формат.
- Нет фейковых отзывов, рейтингов, логотипов партнёров и заявлений о реальных клиентах.

## Чему учит проект

- Разделять данные, типы, страницы и компоненты.
- Работать с React Router и динамическими маршрутами.
- Управлять состоянием фильтров и формы.
- Делать предзаполнение формы из контекста страницы.
- Писать аккуратный mobile-first CSS без UI-фреймворка.
- Проверять пользовательские сценарии, а не только сборку.
